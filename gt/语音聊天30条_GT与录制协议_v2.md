# 语音聊天 30 条 —— Ground Truth 文案与录制协议 (v2, held-out)

用途：在 **v1（`聊天30条_GT文案与录制协议.md`，纯文字形态）** 之外，做一条**同形态但文案全新**的 held-out 录屏，
专门验证泛化并打压 v1 暴露出的剩余失败面（同音字、长语音切段、未转写语音气泡、模板近重复、纯文本通道）。

- 手机① ＝ **被录制**的那台（主视角，它发出的消息显示在屏幕右侧）
- 手机② ＝ 对端
- 共 30 条消息：① 15 条、② 15 条（即 15 个来回）
- 与 v1 的差异：v1 是**纯文字**消息；v2 是**语音为主**的聊天（语音气泡 + 屏幕转文字），
  且**由本表逐条指定"要不要点转文字"**，从而把"视觉通道 / 音频通道"分别置于可测状态。

---

## 1. 录制协议（重要，先看这段）

1. **从空白会话开始**：先把该好友的聊天记录清空。录屏里出现的文本必须正好是这 30 条，
   混进任何别的历史消息都会污染 GT。
2. **严格按序号逐条发送**，两台手机轮流发；一条发完**收起键盘/收起语音面板**再发下一条。
3. **节奏**：每条之间停 **≥3 秒**（画面需要静止够久，管线靠静止帧建行 + 多帧投票纠错）。
4. **开勿扰模式**：任何横幅通知弹出来都会遮住一行文本，直接变成漏检。
5. **不要做**：撤回、编辑、删除、发图片/红包/表情包/emoji、@某人、引用回复。
   全程不改字号、主题、深色/浅色、护眼模式；关自动亮度、关自动旋转；室内光线稳定，避免手影。
6. **语音相关（v2 重点）**：
   - 每条语音时长 **2–6 秒**；**#8 一条 ≥12 秒**（故意让它被切成多条 ASR 段）。
   - **转文字开关按本表执行**：某行 `screen_text` 不是 `-` → 发送后**点"转文字"**让它上屏；
     `screen_text = -` → **不要点转文字**（保留纯语音气泡，屏幕上不出文字）。
   - **接收到的语音必须在 ① 上点"扬声器"外放播放**（微信默认听筒播放，录屏音轨采不到声音）；
     唯一例外是 **#26**：保持听筒/静音播放，故意让录屏音轨采不到它（负样本）。
   - 录制机媒体音量开到 ~50%，保证外放的语音能被录屏音轨采到。
7. **一个录屏文件里连续录完三段**（别分段录，中间空窗会引入状态机噪声）：
   - ① 逐条发送 **#1–#28**。中途**不要手动滚动**——发送本身会自动把视图滚到最新（追加式滚动）。
   - ② 手动**向上滚动**翻到会话顶部，再**向下滚回**最新。慢速、分段：每滚 1–2 屏停 1–2 秒。
     这一段专门复现"同一屏幕位置被后续内容复用"的失败场景。
   - ③ 滚回最新后，再发 **#29、#30**（新消息到达 + 自动滚到底）。
8. 建议 1080p 竖屏、30fps 以上，码率别太低（糊了会掉字）。

## 4. 考点说明（相对 v1 补了什么）

| 考点 | 位置 | 想验证什么 |
|---|---|---|
| 同音字纠错 | #6/#10/#14/#17/#28 | ASR 同音误识（偶现→偶像、环境→黄金、记流水→寄流水）能否被纠正，是否会拖垮严格一对一匹配 |
| 长语音切段 | #8（≥12s） | 一条语音被切成多条 ASR 段时，能否"一句一行"正确拆分，而不是粘成一条（跨消息误并的根因） |
| 未转写语音气泡 | #3 / #11 / #26 | 屏幕只有语音气泡、不出文字时：能在**音频通道**恢复 #3/#11；#26 声音未采集，应报"检测到语音气泡，但对应声音未被录屏采集"，**不得凭空生成文本** |
| 纯文本通道 | #5 / #16 / #22 | 视觉通道单独可用性（不依赖音频） |
| 模板近重复 + 同槽位复用 | #23–#26 | 只差 1 个数字、相似度约 0.97 的模板消息仍能被分开（主要误并来源） |
| 相邻行争抢 | #20 与 #21、#23 与 #24 | 相邻两条互相"够得着"时，排他仲裁是否生效 |
| 字符级 OCR 难点 | #15 / #19 / #21 | URL、文件名、路径是字符错误高发区 |
| 极端行 | #7 / #13 / #8 | 极短行是否被短文本过滤误杀；超长单条的气泡合并 |
| 滚动后新到达 | #29 / #30 | 手动滚动回顶再回到底后，新消息是否漏采 |

## 5. GT 口径（评测时怎么算对）

- **GT = 屏幕上实际渲染出来的文字**（`screen_text` 列，逐字一致；空格/换行不敏感，评测做归一化）。
- **音频 GT = `spoken_text` 列**（语音真实内容），用于音频通道。
- **逐通道召回分母**：
  - 视觉通道：`V = {id | screen_text != '-'}`（本表 27 条）；
  - 音频通道：`A = {id | form == 'voice' and captured == 'yes'}`（本表 26 条）；
  - **最终输出（通道 A）**应覆盖 `V ∪ A` 的并集；`#26`（`captured=no` 且未转写）为**不可达负样本**，不计入召回分母，只验证"未采集提示、不得幻觉文本"。
- 同一文本重复出现不算错：评测用**多重集**口径，每个文本按其"在任一单帧内同时出现的最大条数"计数。
- 被手机状态栏/输入法/导航栏遮挡的行会从 GT 里排除，不计入召回。
- 严格一对一 P/R/F1 只在 `V ∪ A` 上计算。
- 录完把视频交给我（放到 `videos/`），我会跑管线并输出通道 A/B/C 的 P / R / F1、跟踪 ID 纯度/碎片化/ID 切换。
