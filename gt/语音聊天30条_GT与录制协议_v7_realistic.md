# 语音聊天 30 条 —— Ground Truth 文案与录制协议 (v7_realistic, 养猫/宠物话题)

用途：在 **v6_catcare 的 30 条文案**基础上，把合成录屏做得更贴近真实录屏，共三处变化：

1. **聊天区背景 = 一张壁纸图**（不再是纯平色块）；
2. **气泡改为非绿配色**（发=深蓝、收=近白）；
3. **消息之间穿插「系统提示」行**（时间戳 / 撤回 / 已加好友 / 以下为新消息）。

- 手机① ＝ **被录制**的那台（主视角，它发出的消息显示在屏幕右侧）
- 手机② ＝ 对端
- **消息共 30 条**：① 15 条、② 15 条（即 15 个来回），配比与 v6 完全一致；
- **另有 4 行系统提示**（见 §4），不是聊天消息，不参与 30 条的形态配比。

**消息形态配比（严格对齐 v3/v6，勿改）**

| 形态 | 数量 |
|---|---|
| 未转写纯语音（`screen_text = -`，仅音频可恢复） | **22**（含 1 条负样本 #29） |
| 已转写语音（语音气泡 + 屏幕转文字，双通道） | 3（#8 / #18 / #28） |
| 纯文字（仅视觉可恢复） | 2（#4 / #20） |
| 表情包（无任何文本，不可恢复） | 2（#14 / #25） |
| 转账/钱包（屏幕有金额文字，仅视觉可恢复） | 1（#10） |

> 上表 id 为 **v7 的连续编号**（含 4 行系统提示占位），与 v6 的差异仅为插入系统提示后的整体顺延。

负样本口径与 v6 完全一致：
- **#14 / #25 表情包**：无任何可提取文本，管线不得凭空生成文字；
- **#29 未转写 + captured=no**：听筒/静音播放，录屏音轨采不到声音，管线应报"检测到语音气泡但声音未采集"，不得幻觉文本。

**#30 长语音（≥12s）**：故意让它被切成多条 ASR 段，测切段能力。
**#33 / #34 滚动后新到达**：手动滚动回顶再回到底后发送，测管线对"视图被人为滚动"的容忍。

## 1. 录制协议（重要，先看这段）

1. **从空白会话开始**：先把该好友的聊天记录清空。录屏里出现的文本必须正好是本表的
   30 条消息 + 4 行系统提示，混进任何别的历史消息都会污染 GT。
2. **严格按序号逐条发送**，两台手机轮流发；一条发完**收起键盘/收起语音面板**再发下一条。
3. **节奏**：每条之间停 **≥3 秒**（画面需要静止够久，管线靠静止帧建行 + 多帧投票纠错）。
4. **开勿扰模式**：任何横幅通知弹出来都会遮住一行文本，直接变成漏检。
5. **不要做**：编辑、删除、@某人、引用回复（**撤回除外**，见 §4）；不额外发表情/图片
   （本表指定的除外）。全程不改字号、主题、深色/浅色、护眼模式；关自动亮度、关自动旋转；
   室内光线稳定，避免手影。
6. **语音相关**：
   - **转文字开关按本表执行**：某行 `screen_text` 不是 `-` → 发送后**点"转文字"**让它上屏；
     `screen_text = -` → **千万不要点转文字**（保留纯语音气泡，屏幕上不出任何文字）。
   - 每条语音时长 **2–6 秒**；**#30 一条 ≥12 秒**（故意让它被切成多条 ASR 段）。
   - **接收到的语音必须在 ① 上点"扬声器"外放播放**（微信默认听筒播放，录屏音轨采不到声音）；
     唯一例外是 **#29**：保持听筒/静音播放，故意让录屏音轨采不到它（负样本）。
   - 录制机媒体音量开到 ~50%，保证外放的语音能被录屏音轨采到。
7. **表情包 / 转账（#10 / #14 / #25）**：按本表位置发送一个微信默认表情、以及一笔转账
   （金额见 `screen_text`）。这两类**不要点转文字、不发语音**。
8. **系统提示行（§4）**：由微信客户端**自动产生**，不要手动打这些字；只需保证它们
   **出现在对应位置、且可见时长 ≥2 秒**。
9. **一个录屏文件里连续录完三段**（别分段录，中间空窗会引入状态机噪声）：
   - ① 逐条发送 **#2–#31**（即全部聊天消息里"滚动前"的部分）。中途**不要手动滚动**。
   - ② 手动**向上滚动**翻到会话顶部，再**向下滚回**最新。慢速、分段：每滚 1–2 屏停 1–2 秒。
     这一段专门复现"同一屏幕位置被后续内容复用"的失败场景。
   - ③ 滚回最新后，再发 **#33、#34**（新消息到达 + 自动滚到底）；此时微信会自动显示
     「以下为新消息」（#32）。
10. 建议 1080p 竖屏、30fps 以上，码率别太低（糊了会掉字）。

## 2. 视觉样式（图片壁纸 / 非绿气泡）—— v7 相对 v6 的改动

**a) 聊天区背景由"纯平色块"改为"一张壁纸图"**

- 壁纸图：`tests/assets/wallpaper_example.png`，由
  `tests/gen_long_video.py::generate_wallpaper_image()` **程序化生成**（渐变 + 噪点 + 几何图案，
  尺寸 540×1200 覆盖整个聊天区，固定随机种子可复现）。
- **刻意约束**：图中每个像素 R=G=B（中性色）且亮度落在 **[230, 243]**，整幅均值 ≈236。
  这样 `src/visual/chat_scene.py` 的"墙纸占比"判据（中性色且亮度在 [230,244]）仍把整帧
  判为聊天界面，不会把新背景当成"非聊天页面"整帧丢弃。换句话说：**"是一张有纹理的图"
  与"仍落在管线聊天判据带内"两个目标同时满足**。
- 回退开关（保留原来的纯平背景模式）：
  - 代码：`G.make_wechat_realistic_style(use_image_wallpaper=False)`，或直接令
    `style.wallpaper_image = ""`（此时走 `style.bg_color` 纯平底色 #EDEDED）；
  - 命令行：`python tests\gen_voice_chat_video.py ... --flat-wallpaper`；
  - 自定义壁纸：`--wallpaper-image <路径>`。

**b) 气泡配色改为非绿（深蓝 / 近白）**

| 方向 | 屏幕位置 | 气泡底色 | 文字色 |
|---|---|---|---|
| 发（手机①，我方） | **靠右** | 深蓝 `#4C6EF5` = RGB(76,110,245) | 白 `#FFFFFF`（蓝底白字，对比度 ≈4.4:1） |
| 收（手机②，对端） | **靠左** | 近白 `#FAFAFA` = RGB(250,250,250) | 深灰 `#282828`（近白底深字，对比度高） |

- 方向仍**只由左右位置体现**（发靠右 / 收靠左），不依赖颜色；
- 近白 `#FAFAFA` 与壁纸（≈236 浅灰 + 纹理）亮度差约 14 级，肉眼/算法均可区分；
- 语音气泡内的喇叭图标与时长数字随气泡底色取色（深蓝气泡 → 白色图标），不做绿底深字的旧搭配。

## 3. 系统提示行（v7 新增，真实录屏不可避免）

真实录屏里消息之间会夹着**微信自动产生的提示**。本场景插入 4 行，渲染为
**居中 + 小号 + 灰色 + 无气泡** 的文本行（不带头像、不带气泡底色），穿插在消息之间：

| id | 系统提示文本 | 出现位置（真实产生方式） |
|---|---|---|
| #1 | `你已添加对方为好友，现在可以开始聊天` | 会话最顶部：加好友后的系统提示 |
| #9 | `10:23` | 时间分隔条（两条消息之间的时间戳） |
| #15 | `对方撤回了一条消息` | ② 先发一条再立即撤回，被撤回的消息不上屏，只留提示行 |
| #32 | `以下为新消息` | ② 滚回顶部后新消息到达时，微信自动显示的提示 |

口径：
- 这 4 行**不是聊天消息**，不参与 §0 的 30 条形态配比；
- 在最末尾产出的机读 TSV 里以 **`form = system`** 标注（列格式保持不变的 7 列）；
- 逐帧标签 `labels/<id>.labels.jsonl` 与 `labels/<id>.meta.json` 中以
  **`kind: "system"`** 标记，与普通消息的 `kind: "message"` 区分（message 行还含 `sender`/`screen` 等）。

## 6. 考点说明（配比与 v6 一致，另加视觉/系统提示两项）

| 考点 | 位置 | 想验证什么 |
|---|---|---|
| 未转写纯语音（仅音频可恢复） | #2/#3/#5/#6/#7/#11/#12/#13/#16/#17/#19/#21/#22/#23/#24/#26/#27/#30/#31/#33/#34 | 屏幕不出文字时，**ASR 通道**能否独立撑起召回 |
| 已转写语音（双通道对照） | #8/#18/#28 | 同一条语音在"视觉+音频"两路都可达时，跨路去重是否生效、是否重复上屏 |
| 纯文字通道 | #4/#20 | 视觉通道单独可用性（不依赖音频） |
| 无文本消息 | #14/#25 | 表情包无任何可提取文本：**不得凭空生成文本**（负样本口径） |
| 转账/钱包消息 | #10 | 卡片上的金额文字能否被视觉通道正确读出 |
| 长语音切段 | #30（≥12s） | 一条语音被切成多条 ASR 段时，能否"一句一行"正确拆分而非粘成一条 |
| 负样本 | #29 | 未转写 + 声音未被采集：应报"检测到语音气泡但声音未采集"，**不得幻觉文本** |
| 滚动后新到达 | #33/#34 | 手动滚动回顶再回到底后，新消息是否漏采 |
| **图片壁纸背景** | 全片 | 背景非纯平时，聊天界面判定/ROI/去重是否仍稳定（壁纸需落在判据带内） |
| **非绿气泡** | 全片 | 深蓝（发）/近白（收）配色下，气泡分割与"发靠右/收靠左"方向判定是否稳定 |
| **系统提示行** | #1/#9/#15/#32 | 居中灰字、无气泡的行：能否被识别为系统提示而与聊天消息区分（不得当成某一方的消息） |

## 7. GT 口径（与 v6 一致）

- **GT = 屏幕上实际渲染出来的文字**（`screen_text` 列，逐字一致；空格/换行不敏感，评测做归一化）。
  - `screen_text = -` 的条目（未转写语音、表情包）**屏幕上没有文字**，不属于视觉可恢复集。
- **音频 GT = `spoken_text` 列**（语音真实内容），用于音频通道。
- **逐通道召回分母**：
  - 视觉通道：`V = {id | screen_text != '-'}`（30 条消息中 6 条：#4/#8/#10/#18/#20/#28，
    另加 4 行系统提示 #1/#9/#15/#32 —— 它们是屏幕真实文字，按现有评测口径
    `tools/eval_voice_gt.py`（仅排除 `form == 'dialog'`）会计入 V；如需把系统提示单独统计，
    评测侧按 `form == 'system'` 过滤即可，TSV 列格式未变）；
  - 音频通道：`A = {id | form == 'voice' and captured == 'yes'}`（24 条）；
  - **最终输出（通道 A）**应覆盖 `V ∪ A` 的并集；`#29`（`captured=no` 且未转写）、
    `#14/#25`（表情包，无文本）为**不可达负样本**，不计入召回分母，只验证"不得幻觉文本"。
- 被手机状态栏/输入法/导航栏遮挡的行会从 GT 里排除，不计入召回。
- 严格一对一 P/R/F1 只在 `V ∪ A` 上计算。
