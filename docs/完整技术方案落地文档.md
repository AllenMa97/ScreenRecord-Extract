## 1. 文档定位 / Purpose

本系统将**手机录屏视频**自动提取为**结构化文本**（默认聊天记录格式，含 [发]/[收] 气泡归属）。本文档是该系统的**唯一完整落地文档**：从目标约束、流水线架构、每个算法的数学定义与参数语义、数据契约，到工程实现细节（线程模型/缓存/日志/诊断）与测试回归，均可直接指导复现与二次开发。

与 [CV算法重构方案.md](./CV算法重构方案.md)（重构决策记录）和 [技术报告.md](./技术报告.md)（v0.5 框架版）的关系：本文档是**现行实现（v0.8）的权威描述**，前两份为历史演进档案。

## 2. 目标与技术约束 / Goals & Constraints

### 2.1 核心挑战

录屏中大量帧在**语义上完全重复**（静止、滚动位移、回弹），只有少数帧携带新信息（新消息、页面切换、弹窗/toast）。目标：**在不漏内容的前提下把 OCR（外部慢速 API）调用次数降到最低**。

### 2.2 三条设计原则

| 原则 / Principle | 含义 / Meaning | 落地体现 / Where |
| --- | --- | --- |
| 保召回优先 | 采样/去重环节宁多送 OCR，冗余交给下游兜底 | 快进任何变化立即回逐帧；内容指纹复用只省调用不丢内容 |
| 成本不对称 | 误杀=不可逆正确性损失；漏检=可兜底算力损失 | 视觉判定偏向放行；GDE 单证据一律放行 |
| 结构化特征替代标量猜语义 | 滚动=刚体平移(位移)、新消息=局部插入、静止=序列相同；凡是"压成标量+阈值猜"都被替换 | 相位相关判态替代 MAE 分位数；RFSA 序列对齐替代条带 dHash；帧价值连续分数替代状态硬分类 |

### 2.3 性能与成本基线（实测）

- 送 OCR 帧数占视频总帧数 **<9%**（最小 htkf 3.3%，最大 4405 8.7%）
- 长视频（16729 帧 / 6314 行）后处理组装 **468s → 1.16s**（O(n²)→O(n·k)）
- 断点续传 + 内容复用使重跑视频 OCR 调用可降至零

## 3. 总体架构 / Architecture

### 3.1 处理流水线（9 阶段）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 1. 自适应抽帧   FrameSampler：MAE三态 + 相位相关判态 + 步长快进        │
│ 2. ROI 裁剪     RoiManager：剔除状态栏(60px)/导航栏(120px)            │
│ 3. 模糊过滤     BlurDetector：拉普拉斯(弱) AND GDE(强) 双证据         │
│ 4. 视觉去重     VisualDedup + RFSA：粗筛 + 行指纹序列对齐              │
│ 5. OCR 识别     OcrClient：AI Studio API / 本地 / Mock 并发异步        │
│ 6. 文本行跟踪   TextTracker：bbox IoU + 文本相似度逐行跟踪+投票        │
│ 7. 语义去重     SemanticDedup：灰色地带 LLM 仲裁 + OCR 纠错(文本降级)  │
│ 8. 时序状态机   StateMachine：挂起/恢复/gap 检测                       │
│ 9. 内容组装     ContentAssembler：O(n·k) 分桶组装 + 聊天格式           │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 并行架构（隐藏 OCR 延迟）

```
producer(采集线程) ──verdicts队列──→ consumer(主线程, 严格按帧序消费)
        │                                  ↑
        ├─送检帧→ submit_queue(有界背压) → worker池(≤4并发) → poller(统一轮询)
        └─跳过帧→ verdicts直接投递──────────────────────────────┘
```

- **producer**：读帧 → blur → 去重 → 判定（跳过/送 OCR），只把需 OCR 的帧入队
- **worker 池**：并发提交异步任务，在途 job 受令牌限制 `≤ min(concurrent,4)` 防 429；提交/轮询遇 429/5xx 指数退避重试（最多 3 次）
- **poller**：统一轮询结果，乱序完成仍按帧序被消费
- **consumer**（主线程）：状态机 → 文本跟踪 → 组装

### 3.3 两阶段运行

- **预热（warm-up）**：视频开头 45~150 帧密集采样，分布校准阈值（blur 基线预填、去重种子 p50、采样阈值 p30/p75），完成后进入稳态
- **稳态（steady state）**：启用 settle 快照 + 帧价值估计等高级闸门；阈值带在线自适应

## 4. 核心算法方案 / Algorithm Details

### 4.1 抽帧与判态 — 相位相关运动估计（[frame_sampler.py](file:///d:/手机录屏内容提取/src/frame_sampler.py)）

**两套状态信号并存**：

| 信号 / Signal | 方法 / Method | 用途 / Use |
| --- | --- | --- |
| `sampling_state` | MAE 滑动窗口 p30/p75 → static/scrolling/rapid | 采样步长节奏（快进进入判定） |
| `pc_state` | 相位相关（`peak`/`dy`）→ static/scrolling/content_change | settle 运动段/滚动闸门/帧价值（**判定权威**） |

**相位相关判态**（[motion_utils.py](file:///d:/手机录屏内容提取/src/utils/motion_utils.py)）：

```
R = FFT(I_prev) · conj(FFT(I_cur)) / |·|     # 归一化互功率谱
r = IFFT(R); (dx,dy) = argmax(r); peak = r[dy,dx]
```

| 条件 / Condition | 状态 / State | 语义 / Meaning |
| --- | --- | --- |
| `peak ≥ 0.3` 且 `|dy| < 1px` | static | 纯平移（无位移） |
| `peak ≥ 0.3` 且 `|dy| ≥ 1px` | scrolling | 刚体垂直滚动，dy 即位移 |
| `peak < 0.3` | content_change | 内容替换（新消息/弹窗/翻页） |

**运动段判定（双信号 OR）**——`_is_motion_fd`：

```
is_motion = (pc_state != "static") or (mae >= static_floor=2.0)
```

PC 判"内容在动"，绝对像素地板补 PC 盲区：慢速滚动（帧间位移 <1px 但残影使像素漂移）被 PC 读成 static 时不漏。静止帧（MAE≈0 且 pc=static）不受影响。

**快进**：连续静止 0.25s 后渐进快进（最大 1s 步长），任何变化信号立即回逐帧——采样是唯一无法被下游兜底的环节。

### 4.2 模糊检测 — GDE 双证据（[blur_detector.py](file:///d:/手机录屏内容提取/src/blur_detector.py)）

```
blurry = (拉普拉斯 < 相对基线×0.2 或 < 绝对下限6.0) AND (GDE < 2.6)
```

- **拉普拉斯方差（弱证据）**：与文本密度强相关（875~9000），只感知分数下降
- **GDE 梯度方向熵（强证据）**：Sobel 方向直方图香农熵；运动拖影把边缘沿运动方向拉长→方向收敛→熵降；文本密度只影响边缘数量不影响方向分布。实测清晰帧稳定 3.25~3.44，拖影 <2.6，空白=0。**与内容密度解耦，绝对下限无需校准**
- **适用域**：仅对 motion 帧检查（settle 静止帧物理上无运动模糊，检查即误杀——曾致 xxr 后期 11 帧清晰帧全灭）
- **破锁三保险**：连续 5 帧全滤→重建基线+强制放行一帧（failsafe）；窗口 8s 过期→清窗重填；重置时 EWMA(α=0.2) 兜底

### 4.3 视觉去重 — 粗筛 + RFSA 精筛 + 内容指纹复用

**决策链**（[pipeline.py](file:///d:/手机录屏内容提取/src/pipeline.py) producer 内，按序）：

```
① settle 抑制判定(运动段) → 帧价值估计(v0.8, 见第5节)
② 模糊过滤(仅motion帧)
③ 滚动抽稀: 距上次OCR <0.12s 且滚动帧 → 跳过
④ 像素级强去重: 与上一张送OCR图 MAE <1.0 → 跳过
⑤ 视觉去重三档: HIGH_CONF_DUP → 跳过; 否则继续
⑥ 内容指纹复用: 16×16 dHash 与已OCR帧 ≤12 汉明 → 重放缓存行
⑦ 送 OCR
```

**三档置信度**（[visual_dedup.py](file:///d:/手机录屏内容提取/src/visual_dedup.py)）：

| 档位 / Tier | 条件 / Condition | 动作 / Action |
| --- | --- | --- |
| `high_conf_dup` | 行差分 diff < dup_thresh×0.5 | 跳过 OCR |
| `high_conf_new` | diff > new_thresh×0.6 | 送 OCR |
| `gray_zone` | 中间 | RFSA 精筛 |

**RFSA 行指纹序列对齐**（[row_fingerprint.py](file:///d:/手机录屏内容提取/src/row_fingerprint.py)，灰色地带精筛）：

1. **编码**：ROI 降采样灰度（160 宽）按 16px 切行条带 → 每条带 64-bit dHash → 整帧 = 行指纹序列 `S=[f1..fN]`（N≈10~15）
2. **对齐**：带 gap 罚分（-0.3）的 **Needleman-Wunsch 全局比对**，输出 `aligned_ratio` / `new_rows`
3. **实质新行**：匹配对 64-bit 汉明距离 > `rf_noise_floor=14`（绝对噪声地板：同内容 hd≤6，完全不同 hd≥16；**不能用匹配对中位数相对地板**——内容不同时 hd 普遍大、中位数抬高→恒判重复）
4. **多关键帧**：维护最近 3 帧关键帧序列，与全部历史对齐取最优——滚动回看重现旧行匹配更早关键帧→dup；真新内容与所有历史不匹配→new
5. **三档**：`aligned_ratio ≥0.8` 且无新行→dup；有实质新行且 `≤0.4`→new；其余 gray→送 OCR

**内容指纹复用**：送检帧 16×16 dHash 与已 OCR 帧库汉明 ≤12 → 重放缓存行（重新盖章 fid/ts）。解决压缩噪声逐帧累积（~1 MAE/帧）误判"同内容静止帧为新内容"。**这是 settle break/fallback 放行帧的最终兜底**（v0.8 实测 68 次 break 全部被其拦截，零 OCR 增量）。

### 4.4 文本侧（跟踪 / 状态机 / 语义去重 / 组装）

| 模块 / Module | 机制 / Mechanism | 关键参数 / Params |
| --- | --- | --- |
| TextTracker | bbox IoU(0.4) + 文本相似度(0.80) 逐行匹配；窗口 5 帧投票；3s 过期 | `iou_threshold / text_sim_threshold / voting_window` |
| StateMachine | ≥3 行=正常；连续 3 帧密度降 30%=挂起；重叠率恢复；重叠率<0.15 标记 gap | `min_text_lines / suspend_confirm_frames / gap_overlap_threshold` |
| SemanticDedup | 灰色地带 LLM 仲裁（默认关）；文本降级：重叠率>0.92 重复 / <0.60 新；低置信度行 OCR 纠错 | `text_dup_threshold / text_new_threshold / ocr_correction_confidence` |
| ContentAssembler | 长度分桶剪枝 O(n·k) 组装（语义等价守护测试）；bbox 水平位置判 [发]/[收]；无时间戳用 +Ns 兜底 | `chat_format.enabled / center_margin` |

## 5. 送检决策统一模型 — 帧价值估计（v0.8 核心）/ Frame Value

### 5.1 动机

v0.7 之前的送检决策是**状态硬分类打补丁**：settle 抑制 + "content_change 送 / scrolling 抑制" 等 if-else 叠加。弹窗/toast/页面切换/新屏/滚动露出，每种运动模式一个分支，改一处坏一处。**统一改造**：运动段内每帧评连续价值分数，一把尺子。

### 5.2 模型定义（[frame_value.py](file:///d:/手机录屏内容提取/src/frame_value.py)）

```
帧价值 V = novelty × clarity
```

**新颖度 novelty**（两个证据 max 融合，任一强即新内容，效果优先）：

```
replace_evidence = clip(1 - pc_peak / 0.5, 0, 1)      # ① 内容替换证据
novelty = max(replace_evidence, novelty_branch)        # 融合取max
```

① **内容替换证据**：pc_peak 低 = 两帧不是纯平移 = 内容替换（弹窗/toast/切换/新消息）。非刚体运动无需像素对齐，直接强证据。

**novelty_branch 按运动类型分流**：

| pc_state / 分支 | 公式 / Formula | 物理含义 / Meaning |
| --- | --- | --- |
| `scrolling` | `min(1, |est_shift| / h)` | 位移比例 = 滚入新内容比例。滚动动画帧像素差异大+运动模糊，条带对齐后重叠区 MAE 也远超阈值，逐条带判新必然饱和；位移比例免疫这一切（滚半屏≈滚入 50% 新内容才值得送检） |
| `static` / `content_change` | 条带级对齐新颖度（见下） | 位移引导搜索对齐后，MAE>6.0 的新条带比例 |

**est_shift（累积位移）**：帧间 `pc_dy` 积分累积，`content_change` 帧重置；clamp 上限 = `max(value_max_shift=60, 屏高h)`——快速滚动帧间位移 30px+，clamp 必须覆盖整屏否则位移被截断且永久触发短路误判。

**条带级对齐新颖度** `_shift_novelty`：

```
if |est_shift| >= h:  return 1.0                  # 滚动满屏才是全新(短路)
搜索: center=est_shift, 范围 ±8px, clamp=[-cap,cap], cap=max(60,h)
      粗搜(stride=1 引导模式) → 无条件 ±8 精调(像素级)
对齐后按 8 条带: 非重叠区→新; 对齐区 MAE>6.0→新
novelty = 新条带数 / 8
```

**清晰度 clarity**：GDE 闸门 `1.0 if GDE ≥ 2.6 else 0.0`——拖影帧价值归零。

**参考帧维护**：`update_reference(gray_small)` 更新参考并重置 est_shift。**决策即推进**——break/fallback/guard/正常送检/内容复用/EOF 六处都在决策时立即推进，防止滚动段每帧持续 break。

### 5.3 决策规则（[pipeline.py](file:///d:/手机录屏内容提取/src/pipeline.py) settle 分支）

| 规则 / Rule | 条件 / Condition | 动作 / Action |
| --- | --- | --- |
| **break** | 内容替换帧 `value ≥ 0.5`（弹窗/toast/切换/content_change）；滚动帧 `value ≥ 0.75`（滚入3/4屏才构成"新图"） | 立即打破抑制，落正常流程（弹窗/toast/切换/新屏） |
| **fallback** | 距上次 OCR ≥0.12s（纯防抖）且 `novelty ≥ 动态位移门槛`（基线0.75，文本重叠反馈可翻倍至1.0）且清晰 | 兜底送检（滚动中每滚入约3/4屏采样一帧；滚动帧只投票不建新行，冗余由 settle 静止帧兜底召回。实测20260820 f094→f156：f122/137/144/151 全被拦，0.12s配置下全送） |
| **guard** | `pc_state=scrolling` 且距上次 OCR ≥ `scroll_guard_interval=0.7s` 且 `dy ≤ scroll_guard_max_dy=2.0`（仅慢滚动；快速滚动帧不兜底，避免时间兜底推进参考帧抢先抑制自然 break，实测 f137 dy=4 / f139 dy=6 不兜底、f0156 保持 0.76 屏 break）且 `novelty ≥ scroll_guard_min_novelty=0.35` 且清晰 | 滚动长时兜底送检：防慢滚动整段零送检漏中间新消息/toast（实测 f185→f255 段 1.3s 仅滚入 0.69 屏 < 0.75，f223 dy=2 兜底补帧）；该帧照常走文本重叠反馈调门槛。内容门槛防纯时间兜底抢先于自然 break（实测 f132 新颖度 0.22、f137 新颖度 0.31 均被拦，f156 保持 0.76 屏 break；慢滚动 f223 新颖度 0.41 仍兜底） |
| **suppress** | 其余（对齐后无新内容/拖影） | 继续抑制，跳过其余质量闸门 |
| **settle_skip** | 运动结束的 settle 静止帧距上次 OCR `< settle_skip_interval=0.5s`（滚动刚停，画面与最后送检帧大量重复，实测 f156→f174 相距 0.34s 滚入 0.2 屏文本重叠>0.9） | 跳过 settle 帧 OCR（冗余；长滚动整段被抑制时距上次送检远仍送，保兜底召回） |
| **settle_tail_skip** | settle_skip 拦截后的紧接静止帧距上次 OCR 仍 `< settle_skip_interval`（与刚送检帧只差最后滚入量；实测 fb3 中 f175 距 f170 guard 帧 0.09s，像素去重因参考帧在滚动中途而失效误放行） | 一并跳过（与 settle_skip 同一时间门控；新内容在首次出现帧已走 value_break，不受影响） |

> 文本重叠反馈（`scroll_gate_adapt` 事件）：滚动帧送检后，与上一送检帧的 OCR 行重叠率 ≥0.6 判"冗余滚动"（滚入区空白/重复）→ 位移门槛翻倍（封顶1.0）；低重叠=新文本滚入 → 重置基线。送检节奏由"画面文本内容"驱动，时间间隔仅防抖。实测 f156 送检后重叠率 0.973 → 门槛升至 1.0。
>
> 时间兜底的三处仅防"无限空白"（settle 帧无条件冗余、settle 尾静止帧重复、慢滚动整段零送检），不主导节奏：guard/settle_skip/settle_tail_skip 之后的内容判定仍由位移门槛 + 文本重叠反馈闭环完成。

### 5.4 为什么这解决了弹窗/泛化性问题

| 场景 / Scenario | v0.7 硬分类 / Hard classification | v0.8 帧价值 / Frame value |
| --- | --- | --- |
| 弹窗/toast 弹出 | 依赖 content_change 状态恰好被 PC 判中，否则被抑制 | `replace_evidence`（pc_peak 骤降）直接给高分 → break |
| 弹窗小（ROI 占比低） | 无机制 | replace_evidence 可能低，但条带对齐 `new_strips` 仍给比例分 |
| 滚动到新屏 | 靠长滚动间隔抽稀 | 位移比例累积到 0.5 即 break |
| 滚动中间帧（无新内容） | 需逐态打补丁 | 位移对齐后 new_strips≈0 → 抑制 |
| 慢速滚动 | PC 读成 static 漏检 | MAE≥static_floor 双信号 OR 进运动段 + 兜底 |

### 5.5 弹窗排查日志（v0.8 新增诊断）

`settle_value_break` / `settle_value_fallback` / `settle_suppressed` 三条事件的 `extra` 携带**完整评分中间量**（`_value_diag` 透传）：

```
novelty_src(shift_ratio|strip_aligned)  pc_state  pc_peak  pc_dy  est_shift
replace_evidence  novelty_branch  gde  short_circuit
best_shift  best_mae  new_strips  strip_total
```

排查路径：弹窗该送检却缺失 → 查该时刻 `settle_suppressed` 日志——若 `pc_state=static` 且 `replace_evidence` 低 → 弹窗区域占比小、pc 峰未被拉低（候选根因 1）；若 `novelty_src=strip_aligned` 且 `new_strips` 少 → 条带粒度淹没（候选根因 2）。运动段边界日志（`settle_suppress_start` / `settle_snapshot`）同时带 `pc_state/pc_peak/pc_dy` 便于对上车牌。

### 7.2 机制参数（送检/抑制节奏，可调）

| 参数 / Param | 值 / Value | 语义 / Meaning |
| --- | --- | --- |
| `frame_value_enabled` | true | 帧价值总开关；false 回退 v0.7 状态闸门 |

| `value_scroll_break_novelty` | 0.75 | 滚动帧高价值门槛：滚入3/4屏才视为"新图"（0.5屏观感仍"大量重复"，实测 f144=0.51 被拦、f156=0.76 放行） |

| `value_fallback_overlap_high` / `value_fallback_novelty_max` | 0.6 / 1.0 | 文本重叠反馈：滚动帧送检后与上一帧 OCR 行重叠率≥0.6 判冗余 → 位移门槛翻倍（封顶1.0）；低重叠=新文本 → 重置基线 |
| `value_strip_count` / `value_max_shift` / `value_shift_tol` | 8 / 60 / 8px | 新颖度粒度 / 位移 clamp 兜底 / 引导搜索半宽 |
| `settle_skip_interval` | 0.5s | settle 帧门控：滚动结束静止帧距上次送检 <0.5s 时跳过 OCR（滚动刚停画面与最后送检帧大量重复，实测 f156→f174 相距 0.34s 被拦；长滚动整段抑制时距远仍送保兜底）。同一门控也用于 **settle_tail_skip**：settle_skip 后的紧接静止帧（如 f175 距 f170 仅 0.09s，像素去重因参考帧在滚动中途而失效）一并跳过 |

| `scroll_guard_min_novelty` | 0.35 | 滚动兜底的内容门槛：仅当当前帧 `novelty ≥ 0.35` 才兜底送检，防纯时间兜底抢先于自然 break 并清零累计位移（实测 f132 新颖度 0.22 被拦、f137 新颖度 0.31 也被拦，f156 保持 0.76 屏 break；慢滚动 f223 新颖度 0.41 仍兜底） |
| `scroll_guard_max_dy` | 2.0px | 滚动兜底的速度门槛：仅帧间位移 `dy ≤ 2` 的慢滚动才兜底，快速滚动帧一律不兜底——快速滚动的内容在向"一张新图"累积，应由 break 位移门槛收尾，时间兜底推进参考帧会抢先抑制自然 break（实测 f137 dy=4 / f139 dy=6 不兜底，f0156 保持 0.76 屏自然 break；f185→f255 慢滚动段 f223 dy=2 / f293 dy=2 仍正常兜底） |

## 8. 工程实现细节 / Engineering Details

### 8.1 断点续传缓存

OCR 结果按帧指纹增量落盘 `output/cache/{video}_{hash}.jsonl`；重跑命中缓存跳过 OCR。`cache_persist_mock=false` 防止 mock 合成行污染真实缓存（测试专用开关）。

### 8.2 行为日志与诊断帧

- **行为日志**：`output/behavior_log.jsonl`，每事件含 `elapsed_sec / module / event / detail / frame_id / extra`——全流程可回溯，非 LLM thinking 结果
- **诊断帧**：`output/frames/{video}/f0001_t0.02s_static_ocr.jpg`，文件名编码 `{fid}_{ts}_{pc_state}_{decision}`（decision ∈ ocr/ocr_reused/dup/blur/thinned/suppressed/value_break/...），可与日志逐帧对查

### 8.3 关键实现陷阱（踩坑记录，改代码前必读）

| 陷阱 / Pitfall | 后果 / Symptom | 修复 / Fix |
| --- | --- | --- |
| 位移 clamp 上限 < 屏高 | 快速滚动位移被截断，永久触发短路误判全屏全新，滚动段每帧 break | cap = max(max_shift, h)（见 frame_value 注释） |
| 滚动新颖度用条带对齐 | 滚动动画帧重叠区 MAE 远超阈值，逐条带判新饱和 | scrolling 分支改用位移比例 `|est_shift|/h` |
| `abs(est_shift) >= h` 才短路 | 半屏(60px)短路会让 2-3 帧累积即触发 | 整屏才是全新；半屏由条带对齐给比例 |
| 决策时不推进参考帧 | 滚动段每帧持续 break，参考帧陈旧 | 五处决策点 `update_reference` + 重置 est_shift |
| RFSA 噪声地板用"匹配对中位数×3" | 内容不同时 hd 普遍大→中位数抬高→恒判 dup（误杀 97% 内容） | 绝对地板 rf_noise_floor=14 |
| blur 对 settle 静止帧生效 | 文本稀疏页被误杀（xxr 后期 11 帧全灭） | blur 仅检查 motion 帧；校准不抬升绝对下限 |
| GDE 用 1−熵/log(bins) 归一 | 文本行水平方向本身各向异性，基线被抬到不可分离 | 直接用方向熵绝对值 + 弱梯度幅值下限 |

### 8.4 回退开关矩阵（A/B 验证用）

| 开关 / Switch | false 时行为 / Behavior when off |
| --- | --- |
| `frame_value_enabled` | 回退 v0.7 状态闸门 + 间隔抽稀 |
| `pc_enabled` | 回退 MAE≥T1 旧判态 |
| `rf_enabled` | 回退旧条带 dHash 灰色地带 |

## 11. 已知限制与演进方向 / Limitations & Roadmap

| 限制 / Limitation | 现状 / Status | 候选方向 / Candidate |
| --- | --- | --- |
| 弹窗/小区域内容替换：pc_peak 对 ROI 内小占比不敏感 | 有日志诊断，未根治 | 区域级相位相关（分块 peak）或 ROI 分层评估 |
| 价值时间一致性：单帧高价值即 break，静止帧假阳性 | 被内容复用兜底，零成本 | 连续 2 帧高价值才 break（弹窗持续多帧，噪声单帧） |
| 部分行重现（旧行混在新画面）产生 1-2 行 OCR 噪声 | RFSA 多关键帧已缓解 | 更强行指纹判别力（16×16 行级指纹） |
| LLM 语义仲裁默认关闭 | 文本降级兜底 | 按需开启 `llm.enabled` |
| 横向滚动/缩放（非纯垂直刚体） | 位移模型假设垂直平移 | 2D 位移估计 + 仿射补偿 |
