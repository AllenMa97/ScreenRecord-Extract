## 1. 系统概述 / System Overview

本系统以**手机录屏视频**为输入，自动输出**结构化文本内容**（默认聊天记录格式，带 [发]/[收] 气泡归属标记）。核心挑战是：录屏中大量帧在**语义上完全重复**（静止、滚动位移、回弹），只有少数帧携带新信息（新消息、页面切换），必须**在不漏内容的前提下把 OCR（文字识别）调用次数降到最低**。

三个关键设计原则贯穿全文：

1. **保召回优先**：采样/去重环节宁多送 OCR，不可丢内容；冗余交给下游去重与文本合并兜底。
2. **成本不对称**：误杀（滤掉清晰帧）= 正确性损失，不可逆；漏检（放过冗余帧）= 算力损失，可兜底。所有视觉判定偏向放行。
3. **用结构化特征替代标量猜语义**：滚动 = 刚体垂直平移（位移），新消息 = 局部插入，静止 = 序列相同。凡是"把内容变化压成一个标量再用阈值猜"的做法（如纯 MAE 判态、全局 pHash）都被替换为携带语义的结构化特征。

**输入输出 / I/O**：

| 项 / Item | 说明 / Description |
| --- | --- |
| 输入 | 手机录屏 MP4（`videos/*.mp4`） |
| 输出 | 结构化 JSON + Markdown/文本（`output/extracted_content.json` 等） |
| 关键帧保存 | `output/frames/<视频名>/`（诊断用，每帧带状态与判定标签） |
| 行为日志 | `output/behavior_log.jsonl`（逐事件日志，全流程可回溯） |

## 2. 整体架构 / Overall Architecture

### 2.1 处理流水线 / Processing Pipeline

流水线按帧处理，共 9 个阶段（见 [pipeline.py](file:///d:/手机录屏内容提取/src/pipeline.py) 模块头注释）：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 1. 自适应抽帧    FrameSampler：MAE三态 + 相位相关判态 + 步长快进     │
│ 2. ROI 裁剪      RoiManager：剔除状态栏/导航栏                       │
│ 3. 模糊过滤      BlurDetector：拉普拉斯(弱证据) AND GDE(强证据)      │
│ 4. 视觉去重      VisualDedup + RFSA：粗筛 + 行指纹序列对齐           │
│ 5. OCR 识别      OcrClient：AI Studio API / 本地 / Mock 并发异步     │
│ 6. 文本行跟踪    TextTracker：bbox IoU + 文本相似度逐行跟踪          │
│ 7. 语义去重      SemanticDedup：灰色地带 LLM 仲裁 + OCR 纠错         │
│ 8. 时序状态机    StateMachine：挂起/恢复/gap 检测                    │
│ 9. 内容组装      ContentAssembler：行合并 + 聊天格式 + LLM 增强      │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 并行架构 / Parallel Architecture

OCR 是唯一的外部慢速依赖（API 每次数秒），系统以**多线程流水线**隐藏延迟：

```
producer(采集线程) ──帧判定verdicts──→ consumer(主线程, 按帧序消费)
        │                                    ↑
        └──送检帧→ submit_queue → worker池 ──→ poller(统一轮询结果)
```

- **producer**：读帧 → blur → 去重 → 判定（跳过/送 OCR），只把需要 OCR 的帧入队
- **worker 池**：并发提交 OCR 异步任务（在途 job 受令牌限制 ≤ min(concurrent, 4)，防 429 限流）
- **poller**：统一轮询任务结果，写入按帧序消费的队列
- **consumer**（主线程）：严格按帧序消费结果 → 状态机 → 文本跟踪 → 内容组装

### 2.3 两阶段运行 / Two-Phase Execution

- **预热/探索阶段（warm-up）**：视频开头 45~150 帧密集采样，收集统计量，**分布校准各模块阈值**（blur 基线、去重阈值种子），完成后进入稳态。
- **稳态（steady state）**：启用 settle 快照等高级闸门，各阈值带在线漂移自适应（如 blur 基线滑动跟随内容密度）。

## 3. 各阶段算法详解 / Module Details

### 3.1 自适应抽帧 / Adaptive Frame Sampling（[frame_sampler.py](file:///d:/手机录屏内容提取/src/frame_sampler.py)）

**MAE 三态分类**：每帧与上一帧计算降采样灰度图的 MAE（帧间平均绝对像素差），对照自适应阈值 T1（静止）/T2（活跃）分为三态：

| 状态 / State | 判定 / Criterion | 含义 / Meaning |
| --- | --- | --- |
| `static` | MAE < T1 | 静止，内容不变 |
| `scrolling` | T1 ≤ MAE < T2 | 滚动/微小运动 |
| `rapid` | MAE ≥ T2 | 剧烈变化（页面切换等） |

- **自适应阈值 T1/T2**：取 MAE 滑动窗口（120 帧）的 p30/p75 分位数，随视频内容漂移。
- **T1 上限保护（t1_cap_ratio=3.0）**：`T1 = min(p30(窗口), static_floor × 3.0)`，把 T1 锚定在静止地板附近——滚动密集视频的速度窗口 p30 会漂移到滚动 MAE 区间（实测 2.0→23.2），导致滚动帧被误标为静止，滚动质量闸门全部失效。
- **相位相关判态（pc_enabled）**：滚动是刚体垂直平移，相位相关直接估计帧间垂直位移 `dy` 与内容一致性 `peak`（详见 4.3）。`peak 高 + |dy|<1px` = 静止，`peak 高 + |dy|≥1px` = 滚动，`peak 低` = 内容替换。
- **自适应步长**：连续静止确认（0.25s）后渐进快进（最多 1s 步长），任何变化信号立即回到逐帧。
- **滚动抽稀**：滚动动画帧像素差异大但语义常相同，滚动帧最多每 0.12s 采样一帧。

### 3.2 ROI 裁剪 / Region of Interest（[roi_manager.py](file:///d:/手机录屏内容提取/src/roi_manager.py)）

剔除状态栏（顶部 60px）与导航栏（底部 120px），仅保留内容区。周期性（5s）校验边界。ROI 是后续所有视觉特征的裁剪前提。

### 3.3 模糊过滤 / Blur Detection（[blur_detector.py](file:///d:/手机录屏内容提取/src/blur_detector.py)）

**双证据 AND 判定**：

```
blurry = (拉普拉斯低) AND (梯度方向熵 GDE 低)
```

- **拉普拉斯方差（弱证据）**：对文本密度敏感（稀疏页面天然低分），只负责"感知分数下降"。
- **GDE 梯度方向熵（强证据）**：Sobel 梯度方向直方图的香农熵。运动模糊（拖影）把边缘沿运动方向拉长，方向分布收敛 → 熵显著降低；而文本密度只影响边缘数量，不改变方向分布（实测清晰帧 GDE 稳定 3.25~3.44，与拉普拉斯 875~9000 的 10 倍波动无关）。
- **成本不对称**：单证据（内容稀疏或轻微降质）一律放行，交给下游 OCR 置信度兜底；只有两个证据同时成立才判模糊。
- **适用域**：仅对运动/动画中间帧（`is_motion`）检查——settle 静止帧物理上不可能有运动模糊，对其做 blur 纯属误杀（曾导致 xxr 视频后期信息全部丢失）。
- **启发式破锁**（详见 4.5）：连续全滤强制重置、窗口过期重置、EWMA 兜底。

### 3.4 视觉去重 / Visual Deduplication（[visual_dedup.py](file:///d:/手机录屏内容提取/src/visual_dedup.py) + [row_fingerprint.py](file:///d:/手机录屏内容提取/src/row_fingerprint.py)）

两级去重：

1. **粗筛**：行差分剖面（逐行像素差之和）+ 三档置信度（详见 3.4.1）。
2. **精筛（RFSA）**：行指纹序列对齐，灰色地带判定（详见 4.1）。

**三档置信度（方案A）**：视觉去重不再做硬二分，输出三档：

| 档位 / Tier | 条件 / Condition | 动作 / Action |
| --- | --- | --- |
| `high_conf_dup` | diff < dup_thresh × 0.5 | 跳过 OCR |
| `high_conf_new` | diff > new_thresh × 0.6 | 送 OCR |
| `gray_zone` | 中间 | 送 OCR + 标记需 LLM 仲裁 |

**像素级强去重**：与上一张送 OCR 的图 MAE < 1.0 则跳过（压缩噪声兜底）。

**在线阈值校准（方案B）**：OCR 后发现文本完全重复 → 视觉阈值太松，收紧 `diff_dup_thresh`；完全不同 → 太紧，放宽。使视觉阈值自适应当前视频内容特征。

**内容指纹 OCR 复用**：帧内容（160 宽灰度 16×16 dHash）与已 OCR 帧汉明距离 ≤ 12 时直接重放缓存 OCR 结果，不再调用 OCR——解决录屏压缩噪声逐帧累积（~1 MAE/帧）使 MAE/行差分误判"同内容静止帧为新内容"的问题。

### 3.5 settle 快照 / Settle-Based Snapshot

运动段（MAE≥T1 或 pc≠static）开始后**抑制 OCR 送检**，运动结束取第一帧静止帧送 OCR（内容完整清晰，消除滚动半截/乱码帧）；视频在滚动中结束由 EOF 兜底送最后一帧。抑制期间跳过其余质量闸门，滚动垃圾帧不污染去重基线。

**长滚动（>0.4s 未静止）抽稀送检（v0.7）**：持续抑制会丢滚动中露出的新内容——快速滚动实为"离散跳变"（帧间 MAE 高），中间帧本身清晰且携带滚动经过的中间内容（如 20F5 协议条款、4405 支付说明）。超过抑制时长后按 `scroll_min_interval_seconds`（0.12s）抽稀放行中间帧，但**只放行携带新内容的帧**：

- 放行：快速跳变 `content_change`（相位相关 peak 低 = 内容替换）与降速静止帧（`pc_state=static` 但 MAE≥地板），这类帧携带滚动中露出的新内容；
- 抑制：真实滚动位移 `scrolling` 帧（peak 高 + |dy|≥1px），下游按滚动残影过滤且**禁止新建跟踪行**（`allow_new=False`），送检零收益——实测 4405 的 85 次采样中 72 次 scrolling 帧全部新增=0，仅 13 次 content_change/static 帧产生 130 行新增。

冗余由模糊（拖影）/视觉去重/内容复用兜底。短滚动（≤0.4s）仍整段抑制、运动结束送 settled 帧。

### 3.6 OCR 识别 / OCR Recognition（[ocr_client.py](file:///d:/手机录屏内容提取/src/ocr_client.py)）

- **后端**：AI Studio 异步任务 API（PP-OCRv6）/ 本地 / Mock（测试）。
- **滚动残影过滤**：滚动帧 OCR 结果置信度 < 0.65 的行丢弃（滚动残影置信度更低），并过滤日文假名/短中文碎片；静止帧保持 0.5 保召回。
- **断点续传缓存**：OCR 结果按帧增量落盘（`output/cache/`），重跑视频直接复用，不重复调用 API。
- **空结果重试**：空结果自动重提交（最多 3 次），429/5xx 指数退避。

### 3.7 文本行跟踪 / Text Line Tracking（[message_bubble_tracker.py](file:///d:/手机录屏内容提取/src/message_bubble_tracker.py)）

跨帧按 bbox IoU（0.4）+ 文本相似度（0.80）逐行匹配跟踪，同一文本行多帧投票确认（窗口 5 帧），行 3s 未出现视为过期。这是**文本模态的第一层去重**（同一行在不同帧出现只保留一次）。

### 3.8 时序状态机 / Temporal State Machine（[state_machine.py](file:///d:/手机录屏内容提取/src/state_machine.py)）

根据 OCR 统计特征切换系统状态：正常（≥3 行文本）/ 挂起（连续 3 帧文本密度下降 30%）/ 恢复（内容重叠率恢复）等。**gap 检测**：重叠率低于阈值标记为内容缺口（应识别但丢失的帧段），挂起恢复时触发关键帧重置。

### 3.9 语义去重 / Semantic Deduplication（[semantic_dedup.py](file:///d:/手机录屏内容提取/src/semantic_dedup.py)）

灰色地带帧的最终仲裁（LLM 默认关闭，`llm.enabled=false`）：

- **LLM 仲裁**：判断两帧文本是否语义重复、合并去重，并对低置信度 OCR 行纠错。
- **纯文本降级**：LLM 不可用时用文本重叠率判定（>0.92 重复，<0.60 新内容）。

### 3.10 内容组装 / Content Assembly（[content_assembler.py](file:///d:/手机录屏内容提取/src/content_assembler.py)）

- 收集跟踪行，按时间顺序组装为结构化内容。
- **聊天格式**：依据文本行 bbox 水平位置判断气泡归属——靠右 = [发]（我方），靠左 = [收]（对方），居中不标记；视频内无时间戳时用播放秒数（+Ns）兜底。

### 3.11 预热校准 / Warm-Up Calibration

视频开头 45~150 帧密集采样，用观测分布校准：

| 校准项 / Item | 方法 / Method |
| --- | --- |
| blur 基线 | 预热期清晰帧分数预填基线窗口（**不再抬升绝对下限**——拉普拉斯与文本密度相关，预热期密集页的 p5 会把后期稀疏清晰页全部误杀） |
| 去重阈值种子 | 静止段 diff 的 p50 → dup 种子；变化段 diff 的 p50 → new 种子 |
| 采样阈值 | 速度窗口 p30/p75 初始化 |

## 4. 关键算法深入 / Key Algorithms

### 4.1 RFSA — 行指纹序列对齐 / Row-Fingerprint Sequence Alignment

**动机**：滚动录屏是刚体垂直平移，同一行文本在不同帧只发生 y 位移、内容不变。旧的"水平切条带 → 每条带算 dHash"是**位置绑定**的——滚动把同一行从条带 3 挪到条带 2 就被误判为新内容。

**方法**（[row_fingerprint.py](file:///d:/手机录屏内容提取/src/row_fingerprint.py)）：

1. **编码**：ROI 降采样灰度（160 宽）按行切细条带（16px ≈ 一个文本行高），每条带算 64-bit dHash → 整帧编码为**行指纹序列** `S=[f1..fN]`。
2. **对齐**：带 gap 罚分（-0.3）的 **Needleman-Wunsch 全局比对**（生物信息学经典算法）求两帧序列最优对齐，输出 `aligned_ratio`（对齐行占比）、`displacement`（中位位移）、`new_rows`（未对齐行）。
3. **实质新行**：对齐匹配对中 64-bit 汉明距离 > 14 的行视为新内容。14 是**绝对噪声地板**（同内容滚动/静止 hd≤6，完全不同文本 hd≥16）——不能用匹配对中位数相对地板（两帧内容不同时 hd 普遍大，中位数抬高 → 恒判重复，曾致对齐率全为 1.0）。
4. **多关键帧历史**：维护最近 3 帧关键帧序列，compare 与全部历史对齐取 `(aligned_ratio, -新行数)` 字典序最优——滚动回看时旧行能匹配更早关键帧 → 判 dup，真正新内容与所有历史都不匹配 → 判 new。
5. **三档判定**：`aligned_ratio≥0.8` 且无新行 → dup；有实质新行且 `aligned_ratio≤0.4` → new；其余 gray。

**收益**：滚动/回弹位移天然免疫，无需像素阈值；复杂度 O(N²)（N≈10~15 行），<0.1ms/帧。

### 4.2 GDE 双证据模糊检测 / Gradient-Direction-Entropy Dual-Cue

**动机**：单拉普拉斯方差在算法层面不可靠——它与文本密度强相关，基线和阈值都在"猜内容密度"而非"猜模糊"（曾致 xxr 后期 11 帧清晰帧全被误杀）。GDE 与内容密度解耦：运动模糊（拖影）把边缘沿运动方向拉长，方向分布收敛 → 熵降；文本密度只影响边缘数量，不改变方向分布。实测分层：

| 帧类型 / Frame type | 拉普拉斯 | GDE |
| --- | --- | --- |
| 真实视频清晰帧 | 875~9000（随文本密度） | **3.25~3.44**（稳定） |
| 方向性拖影（滚动/运动模糊） | 低 | **<2.6** |
| 高斯模糊（各向同性） | 极低 | 1.98 |
| 纯空白 | 0 | 0 |

判定 `blurry = 拉普拉斯低 AND GDE低`：稀疏页拉普拉斯低但 GDE 高 → 放行；拖影两证据齐 → 滤；单证据一律放行给下游 OCR 置信度兜底。

### 4.3 相位相关运动估计 / Phase-Correlation Motion Estimation（[motion_utils.py](file:///d:/手机录屏内容提取/src/utils/motion_utils.py)）

滚动是刚体垂直平移，帧间关系可用位移量 (dx, dy) 完整描述。相位相关（Phase Correlation，基于归一化互功率谱的频域位移估计）同时输出两个结构化信号：**峰值位置 = 位移 (dx, dy)**、**峰值强度 = 内容一致性 peak**：

- `peak` 高 = 两帧是同一内容的纯平移（滚动/静止）；`peak` 低 = 内容替换。
- `|dy| ≥ 1px` 且 peak 高 = 滚动；`|dy| < 1px` 且 peak 高 = 静止。
- 与绝对像素地板（MAE ≥ static_floor，系统唯一绝对常数）**双信号 OR**：慢速滚动（帧间位移 <1px 但残影使像素漂移）被 pc 读成 static 时，MAE 兜底不漏。

#### 4.3.1 数学原理 / Mathematical Basis

**位移定理（Shift Theorem）**：空间域平移在频域等价于相位旋转，幅值完全不变——"内容没变、只是挪了位置" ⟺ "幅值不变、相位整体旋转"，这正是相位相关能认出纯平移的理论基础。

```
f2(x) = f1(x - dx)   ⟺   F2(u) = F1(u) · e^(-j·2π·u·dx/N)
f2(x,y) = f1(x-dx, y-dy)   ⟺   F2(u,v) = F1(u,v) · e^(-j·2π·(u·dx + v·dy)/N)
```

**归一化互功率谱（核心公式）**：两帧各自 FFT 后，用当前帧频谱的共轭乘以前帧频谱，再按幅值归一化：

```
R(u,v) = [ F1(u,v) · F2*(u,v) ] / | F1(u,v) · F2*(u,v) |
```

代入纯平移关系后幅值 `|F1|²` 被除法约掉，R 退化为纯相位函数：

```
R(u,v) = e^(+j·2π·(u·dx + v·dy)/N)
```

反变换回空间域得到**单位冲激**：

```
r(x,y) = F⁻¹{ R(u,v) } = δ(x-dx, y-dy)
```

**物理意义**：

- **峰值位置 = 位移量 (dx, dy)**：相关平面在位移处出现尖峰，其余位置各频率相位互相抵消 ≈ 0。
- **峰值强度 = 纯平移置信度**：归一化互功率谱模恒为 1，故 peak ∈ [0,1]。纯平移时能量集中成单尖峰（peak≈1）；内容替换时互功率谱相位随机分布、反变换能量摊平（peak 很低）。这就是"位移 dy 大 + peak 高 = 滚动"、"peak 低 = 内容替换"能精确判态的数学原因。
- **对照 MAE**：MAE 逐像素比亮度，光照/阴影/对比度一变就误报；相位相关**丢弃幅值只保留相位差**，而亮度变化主要作用在幅值、几乎不动相位 → 对照明变化天然鲁棒。

#### 4.3.2 实现 / Implementation

核心代码（[motion_utils.py](file:///d:/手机录屏内容提取/src/utils/motion_utils.py#L58-L74)）逐行对应公式：

| 代码 | 公式 | 说明 |
| --- | --- | --- |
| `f1 = np.fft.fft2(prev_gray)` | F1(u,v) | 前向 FFT，空间域 → 频域；先转 float64 防溢出/精度损失 |
| `f2 = np.fft.fft2(cur_gray)` | F2(u,v) | |
| `cross = f1 * np.conj(f2)` | F1·F2* | 互功率谱；共轭实现"两帧相位相减" |
| `denom = np.abs(cross) + 1e-10` | |F1·F2*| | 幅值归一化分母；1e-10 防全黑帧/直流项除零 |
| `r = np.fft.ifft2(cross / denom).real` | F⁻¹{R} | 反变换得相关平面；.real 只取实部，清掉数值误差虚部 |

峰值定位与折叠：

- `np.argmax(r)` 找最大响应，`divmod` 把展平索引还原为 (row=y, col=x)。
- **折叠（wrap-around）**：FFT 假设图像周期性，峰值落在数组后半段时等价于**负方向位移**，需减 h/w（如 h=180、峰值在 row=170 → dy = 170-180 = -10）。
- **方向约定（实测确认）**：返回值是当前帧内容相对上一帧的位移向量，图像坐标系 y 轴向下——内容上移（往下滚动）→ dy>0；内容下移（往上滚）→ dy<0。因此 [frame_sampler.py](file:///d:/手机录屏内容提取/src/frame_sampler.py#L228-L238) 的 `_classify_pc_state` 用 `abs(dy)` 判滚动，只关心幅度不关心方向。

**实测验证**（合成测试：160×180 灰度，四种场景跑 `phase_correlation_displacement`）：

| 场景 / Scenario | dx | dy | peak |
| --- | --- | --- | --- |
| 内容上移 6px（往下滚） | 0.0 | +6.0 | 0.996 |
| 内容下移 6px（往上滚） | 0.0 | -6.0 | 0.996 |
| 内容替换（新画面） | -6.0 | 25.0 | **0.053** |
| 完全静止 | 0.0 | 0.0 | 1.000 |

注意内容替换时 (dx, dy) 是噪声（无真实位移可言），只有 peak=0.053 可信——状态机只信 peak，不信那个位移。

#### 4.3.3 已知边界 / Known Limits

- **FFT 周期假设**：位移超过画面一半时峰值会绕到另一侧，折叠逻辑只能覆盖 ±N/2；真实滚动还有边界出入（新行进入、旧行退出），并非理想环形平移。因此实现前必须先 ROI 裁剪 + 降采样到 160×180——既缩小搜索范围，降采样本身兼作低通滤波，压制高频噪声（高频分量相位最易随机化、拉低 peak）。
- **低纹理帧**：纯色/空白页面频域能量集中于低频、相位信息不足，peak 可能假性失真 → 交由 MAE / GDE（4.2）兜底，不单独信相位相关的 peak。

### 4.4 内容指纹复用 / Content-Fingerprint OCR Reuse

录屏压缩噪声逐帧累积（每帧像素漂移 ~1 MAE），MAE/行差分可能误判"同内容静止帧为新内容"，逐帧送 OCR 造成大量冗余调用。方案：对送检帧计算 160 宽灰度 16×16 dHash，与已 OCR 帧内容指纹库匹配（汉明距离 ≤ 12）→ 直接重放缓存行。

### 4.5 启发式破锁 / Heuristic Deadlock-Unlocking

模糊基线窗口的滑动中位数存在两类风险：全滤死锁（窗口只收非模糊帧，全滤则基线永久冻结）与内容密度漂移（基线卡在历史密集页）。三道保险：

1. **连续全滤强制重置**：连续 5 帧全判模糊 → 用最近分数重建基线（低分位反映当前内容密度）+ 强制放行一帧（failsafe，永不永久过滤）。
2. **窗口过期重置**：窗口 8s 未更新（如长时间空白）→ 清窗重填，恢复后立即适应新内容。
3. **EWMA 平滑**：重置时历史不足，用指数滑动平均作为初始基线。
