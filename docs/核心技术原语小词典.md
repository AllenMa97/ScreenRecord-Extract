# 核心技术原语小词典

> 初学者收藏版。本词典按"从视频到文本"的流水线顺序组织，每个原语给出：中文名 / 英文术语 / 一句话定义 / 在本项目中的用途 / 所在代码位置。
>
> 阅读建议：先顺着 1→2→3 的顺序过一遍概念，再去看对应源码，最后回到本词典当速查手册。

## 1. 视频处理基础

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| 帧 (Frame) | 视频由连续静止画面组成，每一幅画面叫一帧 | 处理的基本单位 | `frame_sampler.py` |
| 解码 (Decode) | 把压缩码流（H.264 等）还原成像素矩阵，是 CPU 最贵的操作 | 每帧都要解码后才能做图像算法 | `frame_sampler.py` |
| read() | OpenCV 读取并解码下一帧（grab + retrieve 一步到位） | 逐帧阶段每帧调用 | `frame_sampler.py#L268` |
| grab() | 只跳到下一帧、不解码，代价极小 | 快进阶段跳过中间帧 | `frame_sampler.py#L315` |
| retrieve() | 解码刚刚 grab 的那一帧 | 快进阶段对"值得看"的帧解码 | `frame_sampler.py#L319` |
| ROI (Region of Interest) | 感兴趣区域：剔除状态栏/导航栏后真正有内容的屏幕区域 | 所有视觉计算都在 ROI 内做，省算力 | `roi_manager.py`、`image_utils.crop_roi` |
| 灰度图 (Grayscale) | 只保留亮度、丢弃颜色 | 帧差/相位相关/模糊检测都在灰度图上做，省 2/3 算力 | `image_utils.to_gray` |

## 2. 运动与变化检测

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| 帧差法 (Frame Differencing) | 两帧逐像素相减，平均绝对差越大 = 画面变化越大 | MAE 速度作为变化量纲 | `image_utils.compute_mae` |
| MAE (Mean Absolute Error) | 平均绝对误差：两帧差异的平均值 | 判断"动没动、动了多大" | `image_utils.compute_mae` |
| 相位相关 (Phase Correlation) | 在 FFT 频域估计两帧之间的位移 (dx, dy) | 区分滚动 vs 内容替换，位移免疫 | `motion_utils.phase_correlation_displacement` |
| 位移量 (dx, dy) | 相位相关估计出的水平/垂直平移像素数 | 滚动时 dy 大，静止时 dy≈0 | `motion_utils.py` |
| 相关峰强度 (peak) | 归一化互相关峰值 [0,1]，越高 = 两帧越接近"纯平移" | peak 高 = 滚动/静止，peak 低 = 内容变了 | `motion_utils.py` |
| 行差分剖面 (Row Difference Profile) | 逐行统计像素差异，得到"哪些行在变"的剖面 | 判断滚动行为、辅助自适应 ROI | `image_utils.compute_row_diff_profile` |
| 状态标签 static / scrolling / rapid | 按 MAE 速度分三档的监测标签 | 仅用于日志/诊断，不影响采样决策 | `frame_sampler._classify_state` |
| 状态标签 content_change | 相位相关 peak 低 = 内容替换（新消息/翻页） | 与 static/scrolling 并列的监测标签 | `frame_sampler._classify_pc_state` |

## 3. 模糊检测

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| 拉普拉斯方差 (Laplacian Variance) | 对图像求二阶导后取方差，值低 = 图像平坦 = 模糊 | 弱证据：感知"分数下降"，但对文本密度敏感 | `image_utils.compute_laplacian_variance` |
| GDE (Gradient Direction Entropy) | 梯度方向熵：运动拖影把边缘沿运动方向拉长，方向直方图熵下降 | 强证据：与内容密度解耦，确认"方向性拖影" | `motion_utils.gradient_direction_entropy` |
| 双证据 AND 判定 | blurry = 拉普拉斯低 AND GDE 低，两个同时成立才判模糊 | 成本不对称：宁多一次 OCR，不丢内容 | `blur_detector.is_blurry` |
| 启发式破锁 (Heuristic Unlock) | 连续全滤重置 / 窗口过期 / EWMA 三种机制 | 防止内容密度切换导致基线失真后永久过滤 | `blur_detector.py` |
| EWMA (指数滑动平均) | Exponential Weighted Moving Average，历史不足时的基线估计 | 破锁时重建模糊基线 | `blur_detector.py` |

## 4. 去重与指纹

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| dHash (差值哈希) | 比较相邻像素梯度生成位串哈希，对水平梯度敏感 | 检测文本行垂直位移、内容指纹复用 | `image_utils.compute_dhash` |
| 汉明距离 (Hamming Distance) | 两个哈希的位差异数 | 判定两帧/两内容是否相似 | `image_utils.hamming_distance` |
| 行指纹 (Row Fingerprint) | 每行内容的紧凑哈希序列 | RFSA 的对齐单元 | `row_fingerprint.py` |
| RFSA (Row-Fingerprint Sequence Alignment) | 行指纹序列 + 序列对齐，位移免疫的视觉去重 | 滚动去重最核心创新：不管滚到哪都能对上"同一行" | `row_fingerprint.py` |
| Needleman-Wunsch 对齐 | 经典序列全局比对算法（动态规划） | 对两帧的行指纹序列做对齐，找"哪些行是同一内容" | `row_fingerprint.py` |
| 多关键帧历史 (Keyframe History) | 保留多张历史关键帧而非只看上一帧 | 防止新内容误判为重复 | `row_fingerprint.py` |
| 噪声下限 (Noise Floor) | 指纹距离低于绝对阈值的才视为同一行 | 抗高纹理背景干扰 | `row_fingerprint.py` (`rf_noise_floor=14`) |
| 三档置信度 | HIGH_CONF_DUP / HIGH_CONF_NEW / GRAY_ZONE | 明确去重、明确新内容、灰色地带 | `visual_dedup.py` |
| GRAY_ZONE 双模态联动 | 灰色地带用第二模态（OCR/LLM）仲裁 | 避免误判：不确定就送去 OCR 问 LLM | `visual_dedup.py` |
| 内容指纹 OCR 复用 | 与已 OCR 帧哈希距离 ≤ 阈值的帧复用结果 | 省 OCR 调用量 | `visual_dedup.py` |

## 5. 采样与调度

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| 自适应步长采样 | 静止时跳帧（快进），变化时逐帧（保召回） | 省 CPU 的核心机制 | `frame_sampler.next_frame` |
| 预热校准 (Warm-up Calibration) | 前 45~150 帧密集采样，用观测分布校准各阈值 | 不用写死绝对阈值，泛化到任意视频 | `pipeline._update_warmup`、`_finalize_calibration` |
| 分位数阈值 (Percentile) | 从已排序观测值插值估计阈值 | 校准 T1/T2、dup/new 阈值、模糊基线 | `image_utils.percentile` |
| settle 式快照 | 运动段抑制送检，等运动结束送第一帧静止帧 | 保证送 OCR 的帧内容完整清晰 | `pipeline.py` |
| 帧价值估计 V = novelty × clarity | 新颖度（位移对齐后的新条带比例）× 清晰度（GDE） | 统一送检决策：弹窗/翻页/新内容都打断抑制 | `frame_value.py` |
| 静止参考帧 (Static Reference) | 快进期间保存的静止灰度帧 | 跳帧解码后与它比较，一有变化立即回逐帧 | `frame_sampler.py` |

## 6. OCR 与文本处理

| 术语 | 含义 | 本项目用途 | 代码位置 |
| --- | --- | --- | --- |
| 生产者-消费者流水线 | producer 采集 → 队列 → worker 池 → poller → consumer 按序消费 | 边标边送，OCR 与采样重叠（类比 PyTorch DataLoader 预取） | `pipeline.py` |
| 断点续传 (Checkpoint / Resume) | OCR 结果按视频指纹增量落盘 jsonl | 中断后跳过已缓存帧，不重复花钱 | `pipeline._init_ocr_cache` |
| 指数退避重试 (Exponential Backoff) | 429/5xx 时按指数递增等待后重试 | 应对 OCR 服务限流 | `ocr_client.py` |
| 在途令牌限流 (In-flight Token Limit) | 同时最多 N 个未完成的 OCR job | 防止提交过多把服务打挂 | `ocr_client.py` |
| bbox IoU | 两个检测框的交并比 | 判断文本行是否在相近位置 | `text_utils.bbox_iou` |
| 编辑距离 (Levenshtein Distance) | 最小编辑操作数，衡量文本相似 | 判断 OCR 文本是否同一行 | `text_utils.levenshtein_distance` |
| 多帧投票 (Multi-frame Voting) | 同一行在多个帧出现，用帧数/置信度加权确定最终文本 | 提高单帧 OCR 错误容忍度 | `data_types.TrackedLine.update_with` |
| 文本行跟踪 (Text Line Tracking) | 逐行跟踪 bbox 位置 + 文本相似度 | 把散落各帧的同一行聚合成一条记录 | `message_bubble_tracker.py` |
| 消息泡锚点 | 用聊天气泡的视觉位置（左右/上下）作为跟踪锚点 | 提升消息流的稳定性 | `message_bubble_tracker.py` |
| 气泡内换行合并 | 几何位置 + 像素验证判断大间距行是否同一气泡 | 解决"一条长消息被截成多行" | `bubble_merger.py` |
| 聊天收发标记 | 按 bbox 水平位置分左右 → [发]/[收] | 无需 layout detection 的气泡归属 | `content_assembler.py` |
| 状态机 NORMAL / SUSPENDED / RESUMING | 基于 OCR 统计特征的时序状态切换 | 处理"长时间无新内容"的挂起与恢复 | `state_machine.py` |
| 语义去重 (Semantic Dedup) | LLM 对文本做语义级去重与纠错 | 视觉层兜不住的同义/错字问题 | `semantic_dedup.py` |

## 7. 关键设计原则速记

| 原则 | 一句话 | 例子 |
| --- | --- | --- |
| 保召回 (Recall-first) | 采样是唯一无法被下游兜底的环节，宁可冗余不可丢失 | 宁多送 OCR，不丢内容；冗余交给 OCR 后去重 |
| 成本不对称 | 模糊/去重判"新"的成本远低于判"错"的成本 | 单证据模糊一律放行；GRAY_ZONE 送去 OCR |
| 校准而非写死 | 阈值从观测分布学，不猜内容密度 | 预热分位数校准 |
| 位移免疫 | 滚动是刚体平移，对齐后再比较 | 相位相关、RFSA |
| 流式而非整载 | 视频永远不全量进内存 | 逐帧解码 + 关键帧落盘 |
